# Papilio 3.0.0

PostgreSQL can now own stored numeric public identities through the optional
permuteseq extension. The public-ID field/entity and repository families live
under PostgreSQL; PublicIDOutput is database-independent native Pydantic aliasing.
See [setup and usage](../guide/public-ids.md).

## Breaking removal of runtime ID encryption

Removed IDEncryption, BaseIDOutput, IDInput/IDOutput, decode_path_id,
get_id_encryption_settings and the create_app/setup_exception_handlers
id_encryptions parameter. NotFoundException no longer accepts the obsolete
identifier_is_public flag. encryption.json and PAPILIO_ENCRYPTION are not read.
Payload encryption in papilio.security.crypto remains available.

Existing application imports and API factory arguments must be migrated before
upgrading. This release does not migrate consumers or their databases. Previously
issued public IDs do not automatically match newly generated IDs; creating a new
column or changing a response alias does not preserve old URLs/references.

Choose an explicit adoption/cutover and data migration for each existing resource
before enabling this capability. Preserve any already issued identifiers that
must remain usable; the removed loader cannot be used as an implicit fallback.
Keep internal primary/foreign keys unchanged, expose stored public identities
at every selected primary/foreign/list/filter/error boundary, and ensure the
required PostgreSQL extension is installed before creating generated columns.

Other database backends retain their existing repositories. PostgreSQL public-ID
DDL fails explicitly when compiled for another backend; no portable generator or
automatic fallback is supplied.
