# Papilio 2.0.0

Enum declarations now select their database representation directly:

```python
from papilio.infra.db.schema.fields import EnumField, NativeEnumField

status: Status = EnumField(Status, default=Status.PENDING)
native_status: Status = NativeEnumField(Status, name="message_status")
```

`EnumField` stores string member values in `VARCHAR`, without an enum check
constraint. `NativeEnumField` stores the same values using SQLAlchemy's native
enum support and its normal fallback on other backends. Both read Python enum
members. `StrEnum`, `FaStrEnum`, and ordinary enums with string values work;
non-string values are rejected instead of being converted implicitly.

## Migrate from 1.x

This is a breaking change in both the API and the default storage mapping.
The old `EnumField(Status)` selected native enum support and stored member
names. For `Status.PENDING = "pending"`, it stored `"PENDING"`. Both new
helpers store `"pending"`.

- For an existing text column already storing member values, remove
  `native_enum=False` and `values_callable=...`. Keep its existing `length`
  and field options. This preserves that column's representation.
- For an existing native enum column, select `NativeEnumField` and retain the
  actual database type name/schema. Migrate its labels from member names to
  the corresponding values before using the new mapping. Account for every
  column/default using a shared enum type and coordinate the application
  rollout; the old and new name/value mappings are incompatible when they
  differ. If names already equal values, label changes are unnecessary.
- For a text column previously storing member names, migrate its stored strings
  and defaults to the enum values. A read of an unmigrated name raises
  `LookupError` when that name differs from the value.
- Changing an existing native enum column to ordinary `EnumField` also changes
  its SQL type to `VARCHAR`; it requires an explicit schema migration.
- Custom `values_callable` mappings must be migrated deliberately to member
  values. Neither callback mappings nor the `native_enum` flag remain public
  options. Use explicit SQLAlchemy/SQLModel declarations if an existing schema
  needs a different mapping.

The helpers do not inspect, rewrite, or migrate existing databases. Verify the
actual type, stored labels, defaults, and consumers before deploying an upgrade.
Explicit string defaults should use the enum value, such as
`server_default=Status.PENDING.value`.

## Short method-owned request scopes

`@request_scoped` now works directly on an async instance method whose
constructor receives the APP `AsyncContainer` as `self.container`. Declare
injected keyword-only arguments as `service: Service = Inject()`; the type is
written once. Ordinary positional/named arguments, defaults and return typing
remain available without a payload declaration or caller cast. See the
[complete example](../guide/request-scopes.md).

Existing explicit `container_getter` bindings and native `FromDishka` markers
remain supported. Injected arguments must be keyword-only; invalid declarations
now fail immediately. Explicitly supplying an injected argument remains an error.

Scope exit still does not commit. Same-task nested calls join the active
operation; independent concurrent calls use separate scopes. Transaction
rollback now shields its awaited cleanup from AnyIO cancellation, preventing
the interrupted cleanup from leaving a checked-out connection behind.
